# Орієнтування в проєкті

Тестер акумуляторів на ESP32 + ADS1115: V, I, P, Ah, Wh, SoC, внутрішній опір,
TFT-індикація, лог на microSD, веб-інтерфейс. Залізо реальне, числа з нього
здобуті вимірюванням — здогадки тут дорого коштують.

## Перед тим, як щось міняти

1. [`AGENTS.md`](AGENTS.md) — правила, спростовані гіпотези, хроніка помилок.
   **Прочитати обов'язково.** Порушення будь-якого з тих правил не дасть
   помилки компіляції — воно дасть неправильні числа.
2. [`docs/WORKLOG.md`](docs/WORKLOG.md) — що, коли й ким зроблено, включно
   з незакоміченим. **Верхній запис — перше, що треба прочитати.**
3. [`docs/measurement_core.md`](docs/measurement_core.md) — журнал рішень і
   стендових замірів: чому саме так, що вимірювалось, чим перевірялось. Сюди ж
   дописувати новий висновок, якщо він з'явився.
4. [`docs/TZ.md`](docs/TZ.md) — технічне завдання, 78 розділів. Посилання
   «§NN» у коді й документах ведуть сюди.
5. [`README.md`](README.md) — дисплей KMR-1.8, розводка, три поправки за
   бібліотекою Adafruit.

## Записувати за собою

**Перед роботою:** прочитати верх [`docs/WORKLOG.md`](docs/WORKLOG.md) і
подивитись `git status`. Якщо в дереві є незакомічені зміни, про які в журналі
нічого — це чужа незавершена робота: **не чіпати ті файли й спитати**.

**Перед тим, як закінчити:** дописати запис у `docs/WORKLOG.md` — коли, хто,
що, чому і в якому стані (зібрано? прошито?). Новіше зверху, чотири рядки.

Це не дублікат `git log`: git каже, що змінилось, журнал каже — навіщо і чи
доведено до кінця. Правило заведене після того, як готове, робоче, але ніде
не описане довге натискання кнопки мало не було затерте наступною моделлю.

## Залізо зайняте

**Не прошивати, поки йде тест** — прошивка обриває запис і втрачає години
розряду. Спитати користувача. Так уже було втрачено TEST_0004 на 11.5 хвилині.

Порт CP2102 відкривається лише одним процесом: при запущеному
`pio device monitor` upload падає з `Could not open port, busy`. Не вбивати
чужий монітор — спитати.

```bash
pio run                                    # усі чотири прошивки
pio run -e tester -t upload                # ядро + TFT + SD + веб
pio test -e native                         # тести інтегратора на хості
```

## Сталі рішення

| Рішення | Чому |
|---|---|
| Ядро вимірювання не блокується ніколи | ні Wi-Fi, ні SD, ні NVS, ні дисплей (§71) |
| Δt з `esp_timer_get_time()` | «dt = 1 c» дає систематичну похибку ємності (§18) |
| Ah/Wh накопичуються в `double` | на `float` за годину набігає **+0.11%** |
| Після зміни PGA стара конверсія недійсна | її не «підправляють», беруть нову (§16) |
| Додатний струм = розряд; полярність у знаку `i_gain` | зберігається разом із калібруванням (§54) |
| У показаннях знака немає | напрямок каже `CHARGE`/`DISCHARGE`; мінус читається як несправність |
| Cutoff нічого не зупиняє | розряд рве плата захисту; cutoff лише мітить ємність |
| Аварія залипає, старт її знімає | умова, що лишилась, підніметься знову |
| Завершення тесту — **пара** умов | струм зник **і** напруга в момент зникнення |
| Старт = новий тест | виняток лише після `resume` (§51) |
| Зміна NVS-структури = підняти версію | інакше налаштування тихо скидаються |
| UI нічого не рахує | усе рахує ядро або system-шар (§52) |
| HTTP кладе команду в чергу | зависла мережа не керує залізом (§39) |
| TFT ініціалізується до SD | спільна шина під мьютексом; навпаки панель не піднімається |
| `platform = espressif32@6.13.0` | ядро 2.0.x, на якому все калібрувалось |
| Кольори лише в `:root` у `STYLE_CSS` | canvas читає їх звідти через `pal()`; TFT має власні |

## Секрети

Пароль Wi-Fi живе **лише в NVS**, задається консольною командою `wifi`. У
файлах проєкту його немає і бути не повинно; на сторінці `/settings` поля для
пароля свідомо нема — HTTP тут без шифрування.
