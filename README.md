# KMR-1.8 SPI (128×160) + microSD на ESP32

Модуль підписаний як ST7735, але **несе ST7789**. Через це стандартний приклад
Adafruit на ньому не працює, а бібліотека додає ще три пастки поверх. Тут —
робоча конфігурація і те, що вже перевірено на живій платі.

Плата: ESP32 DOIT DevKit V1. Фреймворк: Arduino через PlatformIO.
Бібліотеки: Adafruit ST7789 1.11.0, Adafruit GFX 1.12.6.

## Збірка

```bash
pio run -e esp32doit-devkit-v1 -t upload   # робоча прошивка дисплея
pio run -e diag -t upload                  # контрольна мішень для дисплея
pio run -e measure -t upload               # вимірювальне ядро, етап 1
pio run -e tester -t upload                # ядро + TFT, етап 2
pio test -e native                         # тести інтегратора на хості
pio device monitor                         # 115200
```

Порт CP2102 відкривається **лише одним процесом**: якщо `pio device monitor`
запущений, upload падає з `Could not open port, busy`. Закрити монітор.

## Вимірювальне ядро

Друга половина проєкту — тестер акумуляторів на ADS1115: V, I, P, Ah, Wh з
auto-range та калібруванням. Ядро (`src/measurement/`) не залежить від дисплея
взагалі: `measure` — ядро з Serial-консоллю, `tester` — те саме ядро плюс цей
самий TFT як індикатор. Розводка, рішення й відкриті питання — у
[`docs/measurement_core.md`](docs/measurement_core.md), технічне завдання —
у [`docs/TZ.md`](docs/TZ.md).

## Розводка

| Пін модуля | ESP32 | Роль | Примітка |
|---|---|---|---|
| `VCC` | **VIN / 5V** | живлення | на платі AMS1117-3.3 з dropout ≈1 В. Від 3V3 на виході лишається ≈2.2 В — панель тускла й нестабільна |
| `GND` | `GND` | земля | |
| `SCL` | `GPIO18` | SPI такт | це **не** I²C: такт. Той самий пін, що `SCK` картки |
| `SDA` | `GPIO23` | SPI дані | той самий пін, що `MOSI` картки |
| `CS` | `GPIO5` | вибір дисплея | |
| `A0` / `DC` | `GPIO17` | команда / дані | не GPIO2 (світлодіод девкіта + strapping), не GPIO21 (дефолтний I²C SDA) |
| `RESET` | `GPIO4` | скидання | смикає сама бібліотека в `initSPI()` |
| `MISO` | `GPIO19` | дані від картки | дисплею не потрібен; дисплей працює з непідключеним MISO, картка — ніколи |
| `SD_CS` | `GPIO15` | вибір картки | strapping-пін: низький рівень при старті глушить ROM-лог у serial |
| `LED+` / `LED−` | `3V3` / `GND` | підсвітка | живиться окремо від логіки, тому світиться навіть коли контролер мертвий |

**Вільні піни:** `13`, `14`, `16`, `21`, `22`, `25`, `26`, `27`, `32`, `33`.
`21` і `22` свідомо лишені під дефолтний I²C, тому `Wire.begin()` без
аргументів працює.

Пастка на майбутнє: `0`, `2`, `4`, `12`–`15`, `25`–`27` належать **ADC2**, який
не працює при активному Wi-Fi. Для аналогових датчиків з Wi-Fi брати ADC1:
`32`–`36`, `39`.

## Три поправки за бібліотекою

Усі три живуть у [`include/Adafruit_ST7789_KMR18.h`](include/Adafruit_ST7789_KMR18.h)
і всі три обов'язкові. Жодна не є помилкою заліза.

### 1. `setOffsets(0, 0)` після `init()`

`Adafruit_ST7789::init(128, 160)` для нестандартного розміру йде в гілку
«centered» і **центрує вікно в GRAM 240×320**:

```cpp
_rowstart = _rowstart2 = (320 - 160) / 2;   // 80
_colstart = _colstart2 = (240 - 128) / 2;   // 56
```

Малювання їде в середину пам'яті, за межі видимої області — **екран білий**.
Дефолт тут **не нульовий**. Зсуви `protected`, тож дістатись до них можна лише
з нащадка. Не прибирати цей виклик.

### 2. `invertDisplay(false)`

Таблиця `generic_st7789` надсилає `ST77XX_INVON` примусово — у коді Adafruit
цей рядок так і підписаний, `// 7: hack`. Справжнім ST7789 так і треба, цій
панелі ні: **чорний фон показується білим**.

### 3. `setRotation()` перекрито

`Adafruit_ST7789::setRotation()` жорстко пише `ST77XX_MADCTL_RGB` на кожному
виклику. Панелі потрібен **BGR** — біт 3, `0x08` (константи для BGR у
бібліотеці немає взагалі). Дописати `MADCTL` після ініціалізації недостатньо:
наступний `setRotation()` тихо повернe RGB.

## Порядок увімкнення

Дисплей і картка на одній шині SPI, послідовність тут не косметика.

1. Підняти обидва `CS` у HIGH.
2. `SPI.begin(18, 19, 23, -1)` — кастомні піни задаються тут і лише тут.
3. **Ініціалізувати дисплей — до будь-якого звернення до SD.** У зворотному
   порядку ініціалізація дисплея не проходить і екран лишається білим.
4. Пробудити картку: 80 тактів при `CS = HIGH`, далі **`CMD0` і `CMD8`**. З
   одним `CMD0` стара SDSC лишається в проміжному стані, віддає `R1 = 0x05`
   замість `0x01`, і `f_mount` падає з error 3.
5. `SD.begin(SD_CS, SPI, SD_SPI_HZ)` — після повного пробудження монтується з
   першої спроби.

## Симптом → причина

| Симптом | Причина | Що перевірити |
|---|---|---|
| Екран рівномірно білий, підсвітка світить | зсуви GRAM 56/80 | `setOffsets(0, 0)` |
| Чорний фон білий, кольори «негативні» | інверсія увімкнена | `invertDisplay(false)` |
| Червоний і синій переставлені | порядок каналів RGB | `MADCTL \|= 0x08` |
| Структуровані смуги з суцільної заливки | не той драйвер | `init(128, 160)` |
| Картинка тускла й нестабільна | `VCC` на 3V3 | `VCC` → `VIN` |
| `f_mount failed: (3)` | неповне пробудження картки | `CMD0` + `CMD8` |
| `Could not open port, busy` | відкритий монітор тримає порт | закрити монітор |

Корисний прийом: **суцільна заливка одним кольором не може вийти смугастою**
за жодної помилки адресації, зсуву, повороту чи tab-варіанта. Якщо
`fillScreen()` дає смуги — псуються самі дані пікселя. І якщо на екрані
читається текст, потік чистий на рівні бітів.

## Що виявилось не при чому

Ці версії правдоподібні й з'їдають години. Усі перевірені на цьому модулі.

- **Пороги буфера рівнів** — на 3V3 і на 5 В смуги однакові.
- **Частота SPI** — перебір 1 / 4 / 8 / 16 / 32 МГц картину не міняв.
  ST7789 тримає ~62 МГц, ліміт ST7735 у 15 МГц тут не діє.
- **Пін `DC` на GPIO2** — перенесення не виправило (перенести все одно варто).
- **Картка на спільній шині** — 113 КБ прочиталися байт у байт; повне
  вимкнення SD дисплей не лікує.
- **Бітове проковзування такту** — виглядало переконливо (синій `0x001F` при
  зсуві на 11 біт читається як червоний `0xF800`), але причиною не було.
- **Таймінги й повторна ініціалізація** — затримки перед `init()` і
  перевстановлення дисплея в `loop()` не допомагають.

## Аналоговий індикатор

[`src/analog_meter.cpp`](src/analog_meter.cpp) — порт прикладу «Analogue meter»
Bodmer'а з `TFT_eSPI` на `Adafruit_GFX`. Геометрія перенесена один в один;
замінено роботу з текстом, бо в `Adafruit_GFX` немає нумерованих шрифтів і
`drawCentreString()` / `drawRightString()` — вони відтворені через
`getTextBounds()`.

Одну деталь оригіналу **не** переносили: там шкала перемальовується повністю
раз на 2 с, і це дає видиме блимання. Потреби немає — кінчик стрілки має радіус
`98·M_SIZE`, а дуга й засічки починаються зі `100·M_SIZE`, тобто стрілка до
шкали не дотягується.
